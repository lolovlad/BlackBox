# Сопоставление Legacy и vNext

Документ фиксирует функциональность старого Flask-интерфейса, проверенную в `legacy/src/webui`, и её состояние в vNext. Цель переноса — сохранить пользовательские сценарии Legacy, встроив их в новую модель телеметрии, инцидентов и видеозаписей.

## Реализовано в vNext

| Возможность Legacy | Состояние в vNext | Где доступно |
| --- | --- | --- |
| Вход, главная панель, управление ВМ, карты и настройки протоколов | Реализовано средствами Hub и его API. | Веб-интерфейс и `/api/v1`. |
| История аналоговых и дискретных данных и графики | Реализовано на Parquet с постраничным чтением, выбором полей и API графиков. | Страница данных. |
| Журнал переходов алертов оборудования и GPIO | Реализован. Повторные отсчёты активного состояния не создают отдельные переходы. | Страница данных и API аварий. |
| Настройка аварийных правил, проверка выражений, изменение и мягкое удаление | Перенесено: администратор управляет правилами, выражения проверяются по полям карт и битовым подписям. | Страница «Аварии», `/api/v1/emergency-rules`. |
| Вычисление правил и журнал их срабатываний | Перенесено: правила вычисляются асинхронно относительно приёма телеметрии; начало, окончание, условие и имя правила сохраняются. | Страница «Аварии», `/api/v1/emergency-events`. |
| Сбор нескольких алертов в один инцидент | Реализовано на уровне ВМ: инцидент начинается с первого события и завершается после снятия последнего события с учётом post-roll. | История инцидентов и `/api/v1/video/incidents`. |
| Настройка камер, предпросмотр, ручная запись и видеозапись инцидента | Реализовано видеосервисом. При срабатывании используется кольцевой буфер до первого алерта, затем запись продолжается до окончания post-roll. | Страница камер и карточка инцидента. |
| Общий экспорт CSV, ZIP и Excel | Реализованы выбор разделов, ВМ, периода и полей аналоговых/дискретных данных. В CSV GPIO указывается BCM-пин. | Страница данных и `/api/v1/telemetry/export`. |
| Экспорт данных аварийного инцидента | ZIP содержит метаданные, переходы алертов с именами видеозаписей, отдельную таблицу срабатываний аварийных правил, CSV телеметрии, JSON рядов графиков и доступные видеосегменты. | Экспорт карточки инцидента. |
| Видеофайл в строке алерта | Имена доступных файлов видео включаются в строки CSV алертов внутри экспорта инцидента. | `alarms.csv` в ZIP экспорта инцидента. |
| Воспроизведение видео в браузере | MP4 отдаётся напрямую; Matroska преобразуется FFmpeg в потоковый MP4. Также остаётся скачивание оригинального фрагмента. | Карточка инцидента. |
| Очистка временных файлов экспорта | Файлы очищаются после ответа; при старте Hub и затем раз в час удаляются оставшиеся файлы экспорта старше семи дней. | Каталог `.exports`. |

## Оставшиеся ограничения

| Область | Ограничение | Последствие |
| --- | --- | --- |
| Экспорт Excel | Видео нельзя вложить в XLSX; видеозаписи доступны в ZIP и в карточке инцидента. | Для полного комплекта «графики + видео» используйте ZIP экспорта инцидента. |
| Чтение телеметрии при экспорте | Экспорт ограничивает максимальное число точек и собирает выбранную выборку перед формированием файла. | Очень длинный интервал может быть усечён; об этом сообщает манифест ZIP. Потоковая выгрузка больших Parquet-периодов остаётся отдельной задачей производительности. |
| Воспроизведение Matroska | Для перекодирования нужен исполняемый файл FFmpeg в Hub; он добавлен в образ Hub при Docker-сборке. | Вне Docker без FFmpeg API воспроизведения Matroska возвращает HTTP 503, скачивание оригинала доступно. |
| Кольцевой видеобуфер | Буфер зависит от непрерывной работы FFmpeg, свободного диска и корректной конфигурации камеры. | Требуются мониторинг места и политика хранения. Текущий буфер автоматически удаляет сегменты старше окна предзаписи с запасом на сегментацию. |
| Совместимость между Legacy и vNext | Автоматической синхронизации таблиц аварий Legacy с новой БД нет. | Старые записи остаются в Legacy; новая история строится из событий vNext. |
| Большие архивы инцидентов | История использует один SQL-запрос вместо N+1 запросов, но составные события и эпизоды пока выдаются вместе с записью инцидента. | Для очень больших архивов следует добавить отдельную пагинацию эпизодов и событий и измерить производительность на реальном объёме. |

## Проверки переноса

- Правила аварийности используют только безопасные выражения и разрешённые функции `abs`, `min`, `max`, `round`, `len`.
- Имена полей проверяются по картам ВМ; подписи в условиях принадлежности проверяются по секциям `bits`. Строки в динамическом списке `active_alarms` могут быть произвольными.
- Ошибка вычисления на отдельном отсчёте не закрывает уже активное срабатывание правила.
- Начало, обновление и завершение аварийного события атомарны в SQLite; сохранённое событие содержит снимок названия и выражения правила.
- Все маршруты истории и видео требуют авторизации; операции изменения правил дополнительно требуют прав администратора и CSRF-токен.
- Инцидент включает события оборудования, GPIO и аварийных правил одной ВМ и завершается только после снятия всех активных событий.
- ZIP экспорта инцидента включает только видеофайлы, которые существуют и находятся в разрешённых каталогах хранения.
