# Создание карты чтения

Карта описывает, какие регистры Modbus или CAN читать и как показывать их в BlackBox. Файл — обычный JSON. Его загружают на странице **Карты**.

Поле `version` — это имя карты, например `AGC-2_Basic`. Повторная загрузка того же имени создаёт следующую версию: v2, v3. Старые версии остаются в списке. Виртуальные машины, которым назначена эта карта, переключаются на новую версию сами.

## Что означает поле

| `kind` | Как ведёт себя значение |
| --- | --- |
| нет `kind`, тип `uint16` / `int16` / `uint32` | аналоговое измерение |
| нет `kind`, тип `bool` | дискретный статус |
| нет `kind`, тип `bitfield` | обычный алерт: виден в журнале и экспорте, инцидент и видео не открывает |
| `"kind": "alert"` | полноценная авария: журнал, инцидент, запись видео |
| `"kind": "analog"` или `"kind": "discrete"` | принудительно измерение или дискретный статус |

`kind` задаётся на всё поле. У bitfield каждый активный бит становится отдельной строкой с текстом из `bits`.

## Минимальный файл

```json
{
  "schema_version": 1,
  "version": "primer-v1",
  "protocol": "modbus_rtu",
  "preset_id": "v1",
  "requests": [
    {"name": "hr", "fc": 3, "address": 0, "count": 20}
  ],
  "fields": [
    {
      "name": "RPM",
      "display_name": "Обороты",
      "source": "hr",
      "address": 0,
      "type": "uint16"
    },
    {
      "name": "Engine_running",
      "display_name": "Двигатель работает",
      "source": "hr",
      "address": 1,
      "type": "bool"
    },
    {
      "name": "AlarmReg",
      "display_name": "Аварии",
      "source": "hr",
      "address": 2,
      "type": "bitfield",
      "kind": "alert",
      "bits": {
        "0": "Низкое давление масла",
        "1": "Высокая температура"
      }
    },
    {
      "name": "StatusReg",
      "display_name": "Режим",
      "source": "hr",
      "address": 3,
      "type": "bitfield",
      "bits": {
        "0": "Mode1",
        "9": "GB Pos On"
      }
    }
  ]
}
```

`checksum`, `map_id` и `metadata` при загрузке пересчитываются. Их можно оставить в файле, но они не заменяют правильные `requests` и `fields`.

## Запросы

`requests` — блоки чтения:

- `name` — имя источника, на него ссылается `source` поля;
- `fc` — функция Modbus: `1` coils, `2` discrete inputs, `3` holding registers, `4` input registers;
- `address` — начальный адрес запроса;
- `count` — число регистров или битов.

Адрес поля считается от начала его запроса: `address: 0` — первый регистр этого запроса. Поле не должно выходить за `count`.

`protocol`: `modbus_rtu`, `modbus_tcp`, `can` или `simulator`.

## Авария и обычный алерт

Полноценная авария открывает один инцидент на виртуальную машину и включает запись камер. Для этого у поля явно указан `"kind": "alert"`.

Обычный алерт остаётся в живом списке, журнале и экспорте. Инцидент он не открывает и уже открытый не удерживает. Для этого bitfield просто не содержит `kind`. Так отмечают режимы и положения: `Mode1`, `GB Pos On`, `Sync.Start`, `Synchronising`.

Не ставьте `kind=alert` на:

- слова команд (`Control Command`, пуск, квитирование, `Alarm inhibit`, `Alarm ack`);
- слова измерений (`AC Measurement`);
- сводные счётчики числа аварий (`Alarms_total`, `No. of alarms`) — это числа, тип `uint16`.

Если в одном регистре смешаны аварии и статусы, разделите их на два поля с одним `source` и `address`. Аварийным битам дайте `kind=alert`, статусным — поле без `kind`.

Одиночный coil типа `bool` с `kind=alert` попадёт в инцидент как текст `True`. Для понятного названия сделайте bitfield и подпишите бит в `bits`.

## Примеры DEIF

**AGC-2.** Десять полей `AlarmReg_20` … `AlarmReg_79` помечены `kind=alert`. `StatusReg_20`, `StatusReg_23` и `StatusReg_26` оставлены без `kind`: это режимы и положения. Биты `Status relay DI4` и `DI5` вынесены из `AlarmReg_23` в `StatusReg_23`.

**AGC-4.** В `agc4-QSK60.json` (`version`: `AGC-4_Modbus`) `kind=alert` стоят у bitfield, чьё название начинается с `Alarm` или `PM Alarm` (регистры 1000–1063 и 1700–1796). `Control Command`, `AC Measurement` и `PM AC Measurement` оставлены без `kind`.

Файл `AGC-4_Modbus.json` из выгрузки совпадал с `AGC-2_Basic.json`, поэтому в нём размечены регистры AGC-2, а не AGC-4.

## Дополнительные свойства поля

- `display_name` — подпись в таблицах;
- `expr` — формула. Для регистра доступна переменная `x`, например `"x / 100"`;
- отдельное поле `"type": "expr"` может сложить уже разобранные значения: `"AlarmReg_20 + AlarmReg_21"`;
- `scale` и `offset` — множитель и сдвиг числа;
- `decimals` — округление, от 0 до 12.

Имя `active_alarms` само попадает в список алертов. Инцидент всё равно создают только поля с явным `kind=alert`.

## Загрузка

1. Откройте **Карты**.
2. Нажмите **Загрузить** и выберите JSON. Карта сразу сохранится.
3. Чтобы обновить ту же карту, нажмите **Новая версия** на её карточке и выберите новый файл. Имя останется прежним, появится v2, v3 и дальше. Старые версии не затираются.

Предупреждения о неизвестном `source`, пустом `expr` или адресе за пределами `count` появляются при публикации. Поле с такой ошибкой пропускается и не читается.
